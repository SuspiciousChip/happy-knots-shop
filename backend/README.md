# Backend

`server.js` is the active Node.js/Express app. It serves the storefront, category and product pages, Cognito customer login, saved addresses, customer order history, checkout, and the email-allowlisted owner portal. Owner routes enforce authorization on the server, support order status management and analytics, and publish validated made-to-order products with images stored in MongoDB GridFS.

Customer sign-in uses the Cognito Lite classic hosted UI and authorization-code flow with PKCE. The server keeps customer identity in an HttpOnly, signed, server-side session. Public browsing does not create a session document; the login flow creates a short-lived OAuth session, then rotates it after sign-in. Login initiation is limited to ten requests per IP per ten-minute window in Atlas. Cognito owns passwords and email verification; Atlas owns address and order data. Login sessions currently expire after at most one hour, requiring a new sign-in. The local callback is `http://localhost:5050/account/callback`. A public HTTPS URL requires updating the Cognito app client's exact callback and `APP_BASE_URL` before launch.

Checkout requires an authenticated customer and an address stored under that customer's Cognito `sub`. It recalculates prices and availability on the server and commits the order, stock changes, totals, and duplicate-checkout receipt in a MongoDB transaction. Cash on delivery remains available. When live Razorpay credentials and a separate webhook secret are configured, customers can instead pay online. The server creates the Razorpay order, validates Checkout's signature, fetches the payment from Razorpay, and creates the shop order only after the exact payment is captured. A signed, idempotent webhook recovers successful payments if the browser callback is interrupted. The address and phone used for an order are snapshotted into that order.

`razorpay.js` supports strictly separated `rzp_test_` and `rzp_live_` credentials. Set `RAZORPAY_TEST_CHECKOUT=true` locally to show the isolated simulation; it never creates a real shop order, changes stock, or updates sales figures and is unavailable on Render or in production. Live checkout additionally requires `RAZORPAY_WEBHOOK_SECRET`. Configure the live dashboard webhook as `https://www.happyknots.shop/webhooks/razorpay` for `payment.captured` and `order.paid`. The webhook secret must be different from the API secret. Never put either secret in a template, browser script, Git, or customer-visible log.

`database/setup-customer-auth.js` was run once to provision the user pool, confidential app client, and classic hosted UI domain in the AWS project's assigned `ap-southeast-2` Region. It stores IDs and the secret in ignored `.env.mongo`. Do not rerun it for this existing pool.

If the catalog is empty, the local test checkout offers a ₹1 simulated demo. It creates only a Razorpay test order and test record; no shop order or stock change occurs.
